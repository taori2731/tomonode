# TomoNode 0.5.2

Minecraft JavaサーバーのMod検査、構成の記録、Modpackの取り込み、起動結果の確認、隔離・復元を改善する更新です。

## 変更内容

- Forge、Fabric、NeoForgeのModメタデータから、サーバー版・ローダー・ローダー版に対する情報を検査します。Minecraft対応版はメタデータの範囲として評価し、たとえば`[1.20,1.21)`には`1.20.1`を含めます。範囲に関する不確かな情報だけでは起動を止めません。
- Mod本体が宣言するIDと、JAR内に含まれるJar-in-JarライブラリのIDを分けて扱います。複数のModに内蔵された`mixinextras`や`geckolib`だけでは、トップレベルModの重複エラーにしません。実際に同じMod本体が複数配置された場合は重大エラーとして扱います。
- サーバーごとのMinecraft版、ローダー、ローダー版、Java版と、Modのサーバー用・クライアント用・両方・任意・不明の分類をsidecarへ記録します。不明なModを自動的にサーバー用へ分類しません。クライアント用Mod構成のマニフェストを出力できます。
- CurseForgeのエクスポート、Modrinthの`.mrpack`、既存Modフォルダーをローカルで解析し、対応関係、依存関係、配布・取得方法、設定ファイルを確認できます。新しい空の構成を作る場合も、確認済みで配置可能なローカルファイルだけを隔離された一時フォルダーへ準備します。既存サーバーへModpackを直接適用せず、未解決の依存Modや不明な配置は自動で追加しません。
- Javaサーバーの起動ログをローダー別に観察し、Ready表示、致命的な失敗、起動前の終了を起動試行に記録します。通常の警告だけでは起動失敗と判定しません。ログ証拠は件数と行長を制限して保存し、機密値を伏せます。
- 選択したModを、変更前バックアップを作成した後に`.server-hub/quarantine/`へ隔離できます。対象ファイルのSHA-256を確認してから移動し、履歴をsidecarへ保存します。復元時に同名の別ファイルを上書きしません。処理が中断した場合は復旧が必要な状態を記録し、ユーザーの指示なしに自動で巻き戻しません。

## 互換性

- 既存のサーバーフォルダー、Mod、ワールド、設定、バックアップ、SQLite、Credential Manager、`.mshmove`、既存Modプロファイルの形式を一括変更しません。
- Mod管理情報、起動試行、隔離操作は`.server-hub/`内の追加sidecarへ保存します。既存の`.server-hub/disabled/`は変更しません。
- アプリ識別子、Windowsインストール先、Updater公開鍵、更新フィードURL、既存Release資産名は維持します。
- BedrockとPalworldの起動・操作経路は、今回追加したJava Modの起動観察・隔離処理の対象外です。

## 確認状況

- M6隔離操作の対象テスト: 13件成功。
- Rustライブラリテスト: 220件成功、13件ignored。
- リリース時はGitHub ActionsがWindows x64インストーラー、Tauri Updater署名、`latest.json`、`SHA256SUMS.txt`を作成します。生成物を検証し、Releaseへのアップロード後に再取得して同一性を検証した場合にだけ公開します。
- 実際のForge環境での起動・参加確認と、既存インストールからのアプリ内更新確認は別途必要です。自動リリース検証だけでは実機での動作を証明しません。

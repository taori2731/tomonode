## ローカル確認用インストーラー

`artifacts/updates/0.5.14-local-qa/tauri.unsigned.json` は、ローカルNSIS生成時だけ更新署名ファイル生成を無効にする設定です。通常の `tauri.conf.json` の署名設定を変更しません。

```powershell
npm run tauri -- build --bundles nsis --ci --config 'artifacts/updates/0.5.14-local-qa/tauri.unsigned.json'
```

この成果物に検証済みの `.sig` はありません。**配布用の更新ファイルや最新フィードには使いません。** インストーラーの生成だけでは、インストール、既存データ維持、アプリ内更新、実ログイン・購入の受入完了を示しません。既存アプリへ自動でインストールしません。

2026-10-03、NSIS生成が成功しました（releaseビルド6分45秒）。ローカル確認用コピーは `artifacts/updates/0.5.14-local-qa/TomoNode_0.5.14_x64-setup-UNSIGNED-QA.exe`、19,299,958 bytes、SHA256 `B4EEA1FEC7B28603DB6F8F06D1C8AEFE65FEAF197E61BDECA0B0AC2176F20B90`。生成元とコピーのハッシュ一致、PEのMZヘッダー、アプリのFileVersion／ProductVersionが0.5.14であること、生成元に `.sig` がないことを確認しました。releaseの既存未使用項目・linker出力の警告は残っています。検査結果はローカルQAフォルダーの `verification.json` に記録しています。

## 署名・Draftの準備

1. 既存変更を保護しながら、この候補に必要な変更範囲を確認・テストして、承認されたソースをmainへ反映します。現在のdirty worktree全体を無条件にコミット・pushしません。
2. `.github/workflows/sign-windows-release.yml` の版番号限定ガードは `0.5.14`／`v0.5.14` に合わせています。main限定、既存Release／タグの上書き拒否、公開鍵維持、署名検証を残しています。
3. GitHub Actions実行はリモートへの成果物保存・Draft作成を伴うため、実行の承認を得てから行います。入力は `version=0.5.14`、`release_tag=v0.5.14`、`publish=false`。この段階でLatestへ切り替えません。
4. 同じ既存署名鍵で作った最終NSIS、隣接 `.sig`、`latest.json`、`SHA256SUMS.txt` を検証します。失敗したら鍵を差し替えず、候補を公開しません。
5. Draftから再取得したバイト列と署名も検証し、承認されたテスト環境でインストール済みアプリの更新・データ維持・再起動を確認します。ユーザーのアプリ更新画面は本人が操作します。

## 公開・販売の停止点

- Latestの切り替えと更新配布には、確認済みの正確な候補に対する公開承認が必要です。ローカルビルド成功やDraft作成だけで公開しません。
- 課金無効のアプリ更新と、Supporterの本番販売開始は別です。販売には規約全体・プライバシー・販売者表示の公開確認、税と販売地域、本番の支払いから資格反映・契約管理までの受入が必要です。
- `publish=false` のDraft準備は、課金フラグやWebhook配送の有効化許可ではありません。
- 秘密鍵やカード情報はチャットへ送らないでください。GitHubのSecret名確認から、その値を取り出そうとしません。

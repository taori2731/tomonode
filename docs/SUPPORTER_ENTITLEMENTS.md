# Free / Supporter 実装・公開前受入ガイド

更新日: 2026-10-01。0.5.12アプリへ統合した準備実装と、未統合のサービス側計画を区別するガイドです。本番受付開始を示すものではありません。公開版の配信状態はGitHub Releaseで、実機更新の成功は別途確認してください。

0.5.12に含むのはアプリ側の登録数制限・署名資格検証・限定テーマ・Discord通知の準備実装です。既存0.5.11のブラウザ認証、プロフィール、メール変更は維持します。公開鍵は空、本番受付は無効です。以下のWorker資格発行・0005移行・Stripe照合仕様は過去の開発実装に基づく導入計画であり、このブランチのWorkerへは統合していません。公開Worker/D1/サイト/秘密情報の変更や実送信は含みません。

## プランと登録数

| 項目 | Free | Supporter（月額500円） |
| --- | --- | --- |
| 登録数 | 3個まで | 無制限 |
| 公開機能・一括操作・保存・安全停止・既存バックアップ／復元 | 利用可 | 利用可 |
| 先行体験 | 一般公開後 | 対象があるとき任意に有効化 |
| テーマ | 既存標準テーマ | 標準＋限定3種類 |
| Discord運営通知 | 利用不可 | 利用可 |

SQLite `servers` の行数が登録数です。停止中・Javaの全ローダー・Bedrock・Palworldも含め、新規作成、既存フォルダー取り込み、移行パッケージから別サーバーを登録する復元を同じ上限で処理します。既存サーバーへのバックアップ復元は追加登録ではなく制限しません。

Freeの0〜2個は追加可、3個以上は追加不可です。登録済み4個以上はすべて維持します。起動・停止・設定・保存・既存バックアップ等の操作を有料化していません。登録解除は管理対象から外す操作で、フォルダーやワールドの削除とは別です。同じフォルダーの既存整合性検査も維持します。

Rustの追加3経路を共通ロックで直列化し、ファイル処理前に資格・数を検査します。DB挿入は同じSQLiteトランザクション内で数と有効期限を再確認します。作成中の資格切れ等で失敗した場合は新規作成領域を既存の失敗処理で片付けます。取り込み元には書き込まず、登録失敗時はその処理が新しく作った初回バックアップだけを削除します。既存データを上限調整のために削除する処理はありません。

「無制限」は登録数に限ります。CPU・メモリ・回線・同時稼働台数の増加や、サーバーの貸し出しを保証しません。

## 共通の会員資格

アプリ側の権限はRust `MembershipService` が判断します。UI、登録、限定テーマ、先行機能、Discord設定・送信は同じサービスを参照します。React/localStorageのプラン名ではネイティブ権限を得られません。

今後統合するWorkerの `/v1/membership/lease` は既存認証セッションを検証し、署名検証済みWebhookに由来する、指定Price・指定Stripeモード・`active`・将来の支払い期間末を満たす契約だけにEd25519署名資格を発行する設計です。資格はアプリ専用audience、アカウントID、現在のBearerセッションのSHA-256、モード、発行時刻、有効期限、支払済み期間末、解約予約を含みます。Bearerや署名用秘密鍵をReactへ返しません。現行公開Workerではこの資格発行は未実装です。

Rustはビルド時の公開鍵・keyIdで署名と全条件を検査します。鍵・セッション不一致、改ざん、不正な期間、未来の発行、失効資格を拒否します。テストモード資格はdebugビルドでのみ受け付け、releaseビルドでは拒否します。公開実行ファイルに有料モックのスイッチはありません。

### 状態・オフライン方針

- 通常は5分間隔で再確認し、画面の再確認ボタンは即時取得します。HTTPは8秒で打ち切ります。
- 署名資格は最長24時間、かつ支払済み期間末までの短い方で失効します。Windows資格情報マネージャーに資格と最後の確認時刻を保存し、プロセス内単調時刻と保存時刻で時計の巻き戻しを検査します。
- 通信断では有効な署名資格だけを期限内で継続します。資格がない通信断はFree扱いです。署名の期限はUIも1秒間隔で検査します。
- 正常な`active`契約の期間末解約予約は、支払済み期間末まで継続します。終了後はFreeです。
- `past_due`、`unpaid`、終了、期限切れ、未ログインは新しい有料資格を発行しません。オンラインの401/403でキャッシュを破棄します。追加の支払い猶予期間は設けません。
- 支払い失敗直後にオフラインになったPCでは、発行済み資格が最長24時間残る可能性があります。これは通信断でテーマ等を突然変更しないための限定されたオフライン猶予で、即時失効を保証しません。
- ログアウトはまず現在セッションを削除し、その後資格とDiscord待機処理を無効化します。サーバー・ワールド・バックアップには影響しません。

利用者管理のPCではバイナリ自体の変更やシステム権限による攻撃まで完全には防げません。完全な不正防止は主張しません。

## Stripe Webhookと非破壊移行（今後の統合作業・0.5.12に含まない）

この節は旧開発作業ツリーの仕様です。以下の0005移行ファイル・テストWorkerは本ブランチに存在しません。現行認証と組み合わせた移植・独立検証・明示承認が必要です。

既存の署名・タイムスタンプ検証に加え、モード、対象Price、イベントID、イベント作成時刻を確認します。購読状態はStripeから取得した現在値を使い、遅れたinvoiceから独自に有効化しません。D1の照合トークン付き条件更新で同時取得の古い結果を破棄し、同じ秒のイベント競合も処理します。終了済み購読を古いイベントで再有効化しません。新しい購読IDは独立して扱います。

`cloudflare/account-api/migrations/0005_supporter_qualification.sql` は列・索引・照合テーブルの追加だけです。既存アカウントや購読行を削除しません。既存購読は検証モード未設定なので、そのまま有料資格に昇格しません。適切な署名イベントによる再照合が必要です。イベント記録と照合は冪等で再送を許容しますが、外部サービス全体のexactly-onceを保証するものではありません。

移行前に承認済みのD1バックアップを取得し、隔離環境で0001〜0005を検証してください。復旧は旧Workerに戻して追加列・テーブルを残す非破壊方式を優先します。公開DBのDROPや巻き戻しで最新アカウント情報を消さないでください。

## 限定テーマ

Midnight Harbor（青）、Quiet Orchid（紫）、Ember Studio（暖色）の3種類です。背景、カード、入力、ボタン、選択、フォーカスと意味別の状態色をCSS変数で統合しています。Freeは色の見本のみ、適用はネイティブ資格確認が必要です。

標準のダーク／ライト／アクセント設定は上書きせず、限定テーマを上から適用します。アカウント別の限定テーマ選択を資格情報マネージャーに保存し、再起動で復元します。失効・ログアウト時は元の標準テーマへ戻り、限定テーマ履歴は残します。再加入後は再選択できます。ロゴ・背景画像は加工していません。

Windowsのネイティブタイトルバー、OSダイアログ、サーバーが開く外部画面はこのCSSテーマの対象外です。

## Discord Incoming Webhook

Discordで対象チャンネルの設定 → 連携サービス → Webhookから本人が作成・URLを取得し、TomoNodeの設定 → Discord通知でサーバーを選択して登録します。URLは投稿権限を持つ秘密情報です。他人に渡さないでください。

保存しただけでは送信しません。「通知を有効にする」を本人が選び、起動完了・停止完了・異常終了を個別に選択します。テスト通知はサーバー名と内容の確認後だけ送信します。送信先はそのサーバーに登録済みの1件です。URLの全文を再表示せず、Windows資格情報マネージャーに保存します。React/localStorage/ログへ保存しません。

URLは `https://discord.com/api[/v10]/webhooks/{id}/{token}` のみ受け付けます。任意ホスト、ローカル／プライベートIP、認証情報、追加query/fragment、非HTTPS、別ホストへのリダイレクトは拒否します。

### 判定と内容

- 実際のプロセス起動をstartingとして記録し、既存の読み取り専用状態検出でrunningを確認して初めて起動完了を送ります。
- Javaは既存の起動ログ／ping、Bedrockは既存UDP状態確認、PalworldはローカルRESTの実稼働判定を利用します。PalworldのREST監視が利用できない場合、起動完了を推測して通知しません。
- 操作開始を起動完了とは扱いません。正常な停止要求が成功した停止と、予期せぬ終了を区別します。再起動は停止・起動の各通知です。
- 状態復元時は最初の値を基準値とし、昔の起動を再送しません。ポーリング間の短い遷移をすべて検出できる保証はありません。
- 内容は表示名（最大64文字）、イベント、時刻、異常時の短い診断案内のみです。IP、ログ、参加者、チャット、パスを追加しません。0.5.13候補では本人が確認した指定ロール／@here／@everyone、またはメンションなしを選択できます。新規設定は「あり・@everyone」を選択済みですが、通知自体は保存直後オフです。変更時は通知を停止して再確認し、旧設定から全体メンションを自動追加しません。発生時刻はホストPCのタイムゾーン、本文はアプリの9言語設定に従います。

### 送信の上限と失効

サーバー操作から独立した非同期ワーカーで処理します。キュー32件、同じサーバー・同じイベント10秒以内を集約、待機120秒で破棄、送信タイムアウト8秒です。429だけを最大3回試行し、待機1〜30秒、各送信後1秒を置きます。長すぎるレート制限や一般エラーでは終了し、通信失敗の不確かな送信を再試行しません。必ず配送されることや重複ゼロは保証しません。

送信の各試行で登録存続、資格、ログインセッション、通知設定の世代を再確認します。保存・変更・無効化・削除と送信を同期し、変更完了後に古いURLを新規使用しません。すでに送信を開始したHTTPを取り消すことはできません。PC/TomoNodeが動作している間だけ送信し、PC電源断や回線断自体の通知はできません。

資格切れ／ログアウトは有効設定とキューを無効化します。再加入・別セッションでは再有効化が必要で、古い通知をまとめて送りません。削除後の古いURLは使いません。登録解除済みサーバーにも送信しません。

公式仕様: [Webhook](https://docs.discord.com/developers/resources/webhook)、[Rate Limits](https://docs.discord.com/developers/topics/rate-limits)。

1. アプリ側は0.5.11の認証・プロフィールへ統合済みです。ローカルテストと署名済み配信の検証は、インストール済みアプリの更新・本人アカウントによる受入確認とは別です。

3. 秘密のEd25519 JWKをWorker secret `MEMBERSHIP_SIGNING_JWK` にだけ保存します。対応する公開32バイト鍵をbase64url形式で `membership-public-key.json` に固定し、双方のkeyIdを合わせます。現状の公開鍵は空で、資格発行／受理は有効化していません。秘密鍵をソースやCLI引数へ書かないでください。
4. 既存公開認証を維持する `stripe-test-worker.ts` のラッパーを使って承認済み検証環境へ反映します。通常の `wrangler.toml` の古いWorker単体を公開APIへデプロイしてはいけません。テストラッパーは本番キー・liveイベントを拒否し、秘密キー交換だけでは本番化できません。
5. 明示指定のテストアカウントとStripeテスト購読でdebugアプリとの資格取得、期間末解約、通信断、再起動、時計、ログアウト、プロフィール、登録競合を実機確認します。実際の有料購入や公開受付はまだ行いません。
6. 本人が指定・許可したDiscordテストチャンネルで各ゲームの実起動・正常停止・異常終了・429以外のエラーを受入確認します。今回のテストはモック送信のみです。
7. 本番規約・返金／異議申し立て方針・税・問い合わせ・個人情報開示、live対応Workerを別途レビューします。承認前に `supportConfig.enabled` を有効にしたり、有料受付サイトを公開しません。0.5.12の準備版アプリ更新は承認済みですが、決済開始の承認とは別です。

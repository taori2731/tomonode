# 独立Supporter資格・Discord実通知ラボ

本番アカウント・課金・Worker/D1・Windows資格情報を変更しないローカル専用検証です。新しいクラウド資源は作りません。インストール済みアプリのUI・Credential Manager・実ゲームの起動停止・本番認証の受入とは区別してください。

## 起動と入力

```powershell
node scripts/supporter-lab/server.mjs
```

ネイティブテストをコンパイル後、`http://127.0.0.1:1466/` を開きます。架空のSupporter／Free／期限切れを選び、Webhook未入力で資格を検証できます。Supporterでは同じRust署名検証・通知本文生成が動作し、本番モードではテスト資格が拒否されることも確認します。

実通知は、本人が指定したDiscordテストチャンネルで作ったWebhookを画面へ入力してください。URLをチャット・ログ・スクリーンショットに含めません。設定 → 内容確認 → 本人のチェック → 送信ボタンの順です。@here／@everyoneは広くメンションする可能性があるため、ラボの初期値は「なし」です。配布アプリの初期値には影響しません。

## 分離と限界

- IPv4 loopbackだけにbind。Host・Origin・CSRF・HttpOnly SameSite cookieを検査し、任意の外部ページから送信できないようにしています。
- 架空セッションは15分、一時Ed25519署名資格は最長120秒。秘密鍵・セッション・WebhookはRAM内のみ。確認IDは60秒で失効し、使用前に消費します。操作中は資格切替を拒否します。
- `/v1/membership/lease` は架空のRAMセッションだけに `mode=test` 資格を発行します。Stripe決済の照合や本人アカウントへの特典付与ではありません。
- Rustテスト実行ファイルへ秘密情報をstdinで渡します。CLI引数・環境変数・ファイル・結果レスポンスへWebhookやBearerを出しません。実アプリの接続先や空の本番公開鍵は変えません。
- `supporter_lab` と検証入口は `cfg(test)` のみ。Tauriコマンドとして登録せず、debugアプリ・releaseアプリに資格バイパスを組み込みません。
- Rustの実URL検査・本文生成・HTTP executor・429限定の再試行は本体と共通。資格は各試行前に署名・期間・セッションbindingを再検査します。ただし本体のキュー・ゲーム状態・Windows秘密保存をこのラボだけで検証済みとは扱いません。
- HTTP開始後の取り消し・配送・閲覧は保証しません。通信失敗は自動再送しません。Discordへの実送信は明示確認した時だけです。
- タブ終了だけでは即時破棄を保証しません。15分の失効またはサーバー停止（Ctrl+C）で破棄します。UI確認用のエージェント操作はWebhook未入力の検証に限定します。
